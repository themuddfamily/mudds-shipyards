## Proposed modern interpretation

**All choices in this section are new design proposals, not observations of the original game.**

Make Titan a medium utility shuttle for a small travelling party and a small conserved service load. Its payoff is a short, connected cabin/hold route and predictable local docking. Jovian remains the freight/engineer craft; Halyard remains the long-haul carrier with its existing specialist crew stations. Titan needs neither those specialist stations nor a new mission type to earn a distinct role.

- Proposed identity: `titan_provisional`, displayed as `Titan-class Medium Transport candidate`, with `ShipDefinition.EvidenceStatus.PROVISIONAL`. Evidence notes must separate A3's name/role from every modern shape and mechanic. B3/B4 may be cited as label-only evidence, never model references.
- Proposed fitout: one pilot position, two ordinary passenger seats and one connected cargo nook. The seat count is a modern design choice, not historical capacity. Use one physical hatch/ramp route from berth to cabin to helm, with no seat teleport required to traverse the cabin. Start with a simple original hull around that route; dimensions follow player/camera/berth clearance, not guessed source scale.
- Proposed cargo: a four-capacity-unit manifest accepting existing repair-kit cargo, using existing item capacity accounting. These are gameplay units, not tonnes or a historical cargo rating. Use an existing physical terminal transfer pattern; loading consumes real source stock and unloading returns/transfers the same stock. Do not award a new mission payment or loosen Jovian-only delivery eligibility. Passenger occupancy grants no cargo authority.
- Proposed handling starting point: maximum speed 72, boost 90, thrust 18, braking 27, yaw 40, roll 48, hull 220, engine start 3.4 seconds and landing maximum speed 11. These are trial values in existing definition units. They place local response above Jovian/Halyard while giving up Halyard's cruise speed and Jovian's hull margin. Check the actual live roster before freezing tuning; preserve its existing signature contracts rather than changing other craft to accommodate Titan. Do not claim an original handling match.
- Proposed weapon scope: one pilot-fired installation using the existing `assets/weapons/jovian_combat_pulse.tres` profile through the current combat owner, with its existing damage/cadence and no turret or new projectile. This is contemporary reuse, not a historical Titan weapon claim or a new combat specialty. Reuse the normal pilot flight, component damage, service/repair, recall and reset lifecycle. Add no gunner, engineer, loadmaster, navigation station, bed, bespoke weapon or transport simulation to this proposal.
